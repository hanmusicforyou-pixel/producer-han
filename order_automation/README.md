# 영암부부농원 발주 자동화

매일 오전 10시에 네이버 메일에서 업체들의 발주서를 모아 **통합발주서 1개**로 만들어 박경원님(`kwpark462@naver.com`)께 보내고,
박경원님이 운송장번호를 채워 회신하면 **업체별 엑셀 + 안내문**을 각 업체에 돌려보냅니다. 매 단계 결과는 내 네이버 메일로 요약이 옵니다.

```
업체 A ─┐  제목 "10월 5일 영암부부농원 발주서" + 엑셀      ┌─ 업체 A ← 자기 몫 엑셀(운송장 포함) + 안내문
업체 B ─┼──▶ 내 네이버 메일 ──10:00──▶ 통합발주서 ──▶ 박경원 ──회신(운송장)──▶ 분배 ─┼─ 업체 B ← …
업체 C ─┘        │                                          │                       └─ 나 ← 전체 요약
                 └─ 나 ← [자동발주 1단계] 요약 (품목별/업체별 표)   └─ 나 ← [자동발주 2단계] 요약
```

운영 기간: **2026-10-30 까지** (`END_DATE`). 그 뒤에는 실행돼도 아무 것도 하지 않습니다.

## 1. 준비 (한 번만)

### 네이버 메일 설정 (k333896 계정)
1. 네이버 메일 → 환경설정 → **POP3/IMAP 설정** → IMAP/SMTP **사용함** 저장
2. 네이버 **2단계 인증을 켜고** → 내정보 → 보안설정 → 2단계 인증 관리 → **애플리케이션 비밀번호** 발급. 이 발급된 비밀번호를 사용합니다.
   **평소 로그인 비밀번호는 거부됩니다.** 2단계 인증을 꺼 둔 상태에서는 앱 비밀번호를 만들 수 없어 로그인이 계속 실패합니다. (실제로 2단계 인증을 해제하고 일반 비밀번호로 시도했을 때 `Authentication failed` 가 났고, 켜고 앱 비밀번호를 쓰자 성공한 사례가 있습니다)
3. GitHub Actions(아래 방법 A)로 돌릴 경우 → 내정보 → 보안설정 → **해외 로그인 차단 → 해제**
   (GitHub 서버가 해외에 있어서 켜져 있으면 로그인이 막힙니다. PC에서 돌리면 필요 없음)

> 비밀번호는 아래 Secrets 또는 PC의 `.env` 파일에만 넣습니다. 채팅·코드·메일에 적지 마세요.

### 방법 A. GitHub Actions 로 자동 실행 (권장 · PC 꺼도 됨 · 무료)
1. 이 저장소 → **Settings → Secrets and variables → Actions → Secrets → New repository secret**
   - `NAVER_APP_PASSWORD` = **애플리케이션 비밀번호**(평소 비밀번호 아님)  ← **이것 하나만 필수**
   - (`NAVER_ID` 는 코드에 `k333896` 기본값. 다른 계정이면 Secret 으로 추가)
2. 같은 화면 **Variables** 탭 → `MY_NAME`(안내문 서명 이름), `MY_PHONE`(연락처) 추가
3. **Actions 탭 → "영암부부농원 발주 자동화" → Run workflow → command: `test-login`** → 초록색이면 연결 성공
4. 끝. 이후 매일 한국시간 10:00~20:30 사이 30분마다 자동 실행됩니다 (`.github/workflows/order-automation.yml`).

수동 실행도 같은 화면에서 합니다.

| command | 하는 일 |
|---|---|
| `run` | 지금 시각 기준으로 필요한 단계 수행 (자동 실행과 동일) |
| `test-login` | 네이버 IMAP/SMTP 로그인만 확인 |
| `announce` + `to` 에 업체 메일 | 업체에 "발주 접수 안내" 공지 발송 (최초 1회) |
| `preview-announcement` | 공지 문구 출력만 |
| `collect` / `check-reply` | 1단계 / 2단계만 따로 |
| `dry_run` 체크 | 실제 발송 없이 로그만 |

### 방법 B. 내 PC에서 실행
```bash
cd order_automation
pip install -r requirements.txt
copy .env.example .env      # (맥/리눅스: cp .env.example .env) → 메모장으로 열어 비밀번호·이름·전화 채우기
python main.py test-login   # 로그인 확인
python main.py demo         # 네이버 접속 없이 전체 흐름 시연 (data/demo 폴더에 결과)
python main.py daemon       # 켜두면 매일 10:00 수집, 30분마다 회신 확인
```
PC가 10시에 켜져 있어야 합니다. 작업 스케줄러/cron 을 쓰려면 `python main.py run` 을 30분마다 실행하도록 등록하세요.

## 2. 업체에 알려야 하는 규칙
- 메일 제목: **`○월 ○일 영암부부농원 발주서`** (예: `10월 5일 영암부부농원 발주서`, 괄호 없이 숫자만). 제목의 날짜로 그날 발주를 모읍니다. `10월5일`, `10월 05일`, `RE:`가 붙은 것, 업체가 `(10)월 (5)일`로 쓴 것도 인식합니다
- 마감: **매일 오전 10시**. 10시 이후 도착분은 통합에 포함되지 않고, 나에게 `[자동발주 지각접수]` 메일이 옵니다 (수동 처리)
- 첨부: 엑셀 1개, 기존 양식 (`받는분성함 / 받는분주소 / 받는분전화번호 / 박스수량 / 품목명 / 보내는분성명 / 보내는분전화번호` 열). 열 순서가 달라도, 헤더 이름이 비슷해도(수령인/상품명/수량 등) 자동 인식합니다
- 공지 문구와 매일 나가는 안내문 전문은 **[docs/업체_안내문.md](docs/업체_안내문.md)** 참고

## 3. 나에게 오는 메일 (제목 앞머리)
| 제목 | 의미 |
|---|---|
| `[자동발주 1단계] 10월 5일 … 통합발주 완료` | 박경원님께 보냄. 품목별·업체별 표 + 통합발주서 첨부 |
| `[자동발주 2단계] 10월 5일 … 업체 안내 발송 완료` | 회신 확인 후 업체별 발송 끝. 업체별 파일 전부 첨부 |
| `[자동발주 미접수] …` | 10시에 발주서 메일이 하나도 없음 (하루 1회, 이후 도착하면 자동 진행) |
| `[자동발주 지각접수] …` | 통합 발송 뒤에 도착한 발주서. 첨부 붙여서 알려줌 → 직접 전달 |
| `[자동발주 오류] …` | 엑셀을 읽지 못함 → 첨부 양식 확인 |

이 완료 메일들이 **상태 저장소** 역할을 합니다. 다음 실행에서 같은 날짜 완료 메일이 보이면 그 단계를 건너뛰므로, 몇 번을 실행해도 박경원님·업체에 중복 발송되지 않습니다. 지우지 마세요(지우면 다시 보냅니다).

## 6. 문제가 생기면
| 증상 | 확인 |
|---|---|
| test-login 실패 (로그인 오류) | ① 2단계 인증이 켜져 있고 **앱 비밀번호**를 넣었는지(평소 비밀번호는 거부됨) ② IMAP/SMTP 사용함 저장 ③ GitHub Actions 면 해외 로그인 차단 해제 |
| Mac 에서 `CERTIFICATE_VERIFY_FAILED` | python.org 에서 설치한 파이썬의 인증서 문제. 코드는 certifi 인증서를 자동 사용하며, 그래도 나면 '응용 프로그램 > Python 3.x > Install Certificates.command' 를 한 번 실행 |
| `[자동발주 오류]` 엑셀 못 읽음 | 첨부 첫 줄에 `받는분성함`·`품목명` 비슷한 헤더가 있어야 함 |
| 회신이 왔는데 2단계가 안 옴 | 박경원님이 `kwpark462@naver.com` 외 주소로 보냈는지 확인. 제목에 "영암부부농원"이 있거나 엑셀이 붙어 있으면 인식 |
| 매칭 안 된 행 | 2단계 요약 메일 하단 "매칭되지 않은 회신 행" 목록 → 수동 확인 |

실행 기록은 Actions 탭(또는 PC `data/logs/`)에 남습니다. `data/` 폴더에는 고객 개인정보(엑셀)가 들어가므로 깃에 올라가지 않도록 `.gitignore` 되어 있습니다.
